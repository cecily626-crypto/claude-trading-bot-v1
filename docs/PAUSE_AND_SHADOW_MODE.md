# 策略暂停 + 影子模式 (2026-08-01)

## 背景：2026-07-31 行情过滤器回测结论

对策略1（趋势+突破）和策略2（2.0空）分别测试了 ADX/EMA 体制过滤 + universe 收窄，
样本内/样本外(H2)拆分，n<5 标注样本不足，极端值检验，4h/日线周期敏感性交叉验证。
回测脚本与完整日志跑在 VPS 隔离目录 `/root/regime_filter_study/`（不在本仓库内，
只回测未上线，未修改本仓库任何文件）。

### 策略2（2.0空）

| 版本 | 样本外(H2) n | 样本外 PF |
|---|---|---|
| 原版(全量universe) | 221 | 0.65 |
| +BTC站上4h EMA200禁止开空 | 196 | 0.44（更差） |
| +BTC站上日线EMA200禁止开空 | 221 | 0.65（和原版完全一样——样本外窗口里BTC全程没站上日线EMA200，过滤器零触发） |
| +4h过滤+收窄到流动性前5 | 27 | 0.37（更差） |

结论：过滤器在4h维度上生效但让结果更差，在日线维度上完全不生效。两个周期都不支持"过滤有用"。

### 策略1（趋势+突破）

| 版本 | 样本外(H2) n | 样本外 PF |
|---|---|---|
| 原版(当前默认参数) | 231 | 0.67 |
| +ADX过滤(震荡期停手) | 180 | 0.56（更差） |
| +ADX过滤(震荡期只做多) | 193 | 0.59（更差） |
| +EMA过滤(震荡期停手) | 63 | **1.46**（唯一>1的结果） |
| 只做多(无过滤,对照) | 56 | 0.83 |
| +ADX过滤+收窄到流动性前5 | 79 | 0.84 |
| 日线ADX过滤(周期对照) | 133 | 0.98 |

唯一那个 PF=1.46 的结果没能通过换周期复核：换成日线EMA重算同一条规则，全周期
(不分训练/测试)PF直接掉到0.88(<1)，样本外段只剩2笔交易，样本不足。而且这组本身
训练期(H1)PF只有0.41、测试期(H2)反而1.46——其它所有分组都是"训练好、测试差"的
正常衰减模式，只有这组反过来，是典型的过拟合信号。按纪律"两个周期结论不一致=不
可靠"，这个正结果不成立。

### 体制标签稳定性

ADX 的 4h/日线一致率：btc 47.2%、eth 47.7%、doge 50.8%、shib 46.8%、pepe 52.5%——
跟另一个项目(EIGEN range strategy)之前发现的46.4%几乎一样脆弱。EMA的一致率明显更高
(60-82%)，但即便如此，唯一那个"看起来有效"的EMA过滤结果换周期后还是塌了。

**结论：ADX/EMA 体制标签在这两套策略的universe上都不够稳定，不能作为恢复交易的判断
依据。**

### 最终判定

所有有效样本量的分组，样本外PF全部<1。唯一一次>1的结果没能通过换周期复核，视为
不可靠。两套方向性策略在当前市场没有边缘。正确做法是暂停，等市场出现明确趋势/下跌
行情、且用结果本身（而不是脆弱的体制标签）确认之后再恢复。

## 暂停执行 (2026-08-01)

`trading_control.json`：
```json
{
  "strategy1_trading_enabled": false,
  "strategy2_trading_enabled": false
}
```

`paper_bot.py` / `paper_bot_short.py` 在"开新仓"分支前各加了一行开关判断（
`trading_enabled("strategy1_trading_enabled")` / 通过既有的 `reason` 跳过链加了
`"paused"` 分支）。策略逻辑（信号计算、止损、仓位管理）完全没动。已有持仓（暂停时
策略2持有 memecoin 空单 + troll 空单共2笔）按原规则自然离场（硬止损/移动止损/账户
熔断），不做人为强平。

## 影子模式

`paper_bot.py` / `paper_bot_short.py` 里各加了一套完全独立的影子账户
(`shadow_account.json` / `shadow_account_short.json`)，用和真实账户完全相同的
入场/出场/仓位规则（含硬止损、账户熔断、opt#4滚动PF仓位缩放），唯一区别是它永远不
受 `trading_control.json` 开关影响——持续模拟"如果没有暂停会怎样"。每笔影子开平仓
都写进共享的 `shadow_trades.csv`（用 `strategy` 列区分 `S1_trend_breakout` /
`S2_short`）。

`weekly_review.py` / `weekly_review_short.py` 已改为读 `shadow_trades.csv`，推送
滚动60天/90天的影子PF、胜率、交易笔数、累计假设盈亏，保留原有Telegram前缀，并注明
"策略已暂停，以下为影子模拟"。原来的"重新跑一次滚动~50天回测"方式已废弃——影子账户
是持续演算的实盘模拟，比重新回测更贴近"如果没暂停会怎样"这个问题。

## 恢复条件

**不使用ADX/EMA体制标签**——已验证4h/日线一致率只有47-52%，不可靠。

改用结果导向：`resume_watch.py` 每个5分钟周期都检查一次，条件是

> 滚动90天影子PF > 1.2，且期间影子交易 ≥ 30笔，两者同时满足

PF门槛定1.2而不是1.0，是留缓冲避免在1.0附近反复横跳。达到条件时给对应策略推一次
Telegram提醒（边沿触发，不会每5分钟刷一次；条件跌破后又重新达到会再提醒一次），
**但绝不会自动把 `trading_control.json` 里的开关改回 `true`**——恢复交易必须手动
确认、手动改这个文件。

两套策略的恢复条件各自独立判断（`S1_trend_breakout` / `S2_short` 分开算）。
